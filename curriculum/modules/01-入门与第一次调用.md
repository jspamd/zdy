# 1. 入门与第一次调用

## 学习目标

说清大模型应用在做什么，并成功调通一次接口。

完成标准：能独立发出一次聊天请求，并解释温度和上下文窗口。

## 课时

<a id="1-1"></a>

### 1.1 应用地图

**要点**

- 模型根据这一次给它的上下文生成下一段文字。它看不到你的私有文件，除非你把内容放进上下文，或接上工具。
- 提示词是你写的指令和材料，不是模型自带的知识开关。
- 上下文是这一次请求里模型能看到的全部内容：指令、历史、检索片段、工具结果都算。
- 工具是你的程序去执行的动作，例如计算、查时间、请求接口。模型只决定要不要调用。
- 检索是先从文档里找出相关片段，再放进上下文。检索不执行动作，工具不负责「找段落」。

**练习**

画一张你的第一个小应用地图。标出模型、提示词、上下文、工具、检索里，第一版会用哪几块，哪几块先不用。在图旁用一句话写出工具和检索的差别。

**自检**

- [ ] 五块都出现在图上或「先不用」的说明里
- [ ] 能说出：检索是把材料放进上下文，工具是程序去执行动作

- [ ] 进行中

### 1.2 Token、上下文窗口、温度、费用

**要点**

- Token 是计费和长度单位。中英文切分方式不同，不要用字数代替 token 数。
- 上下文窗口是单次请求的上限。提示、历史、检索片段和模型回复都占这个上限。
- 温度越低，同一问题多次输出越稳定；越高越发散。要交给程序解析时，用低温。
- 费用随输入 token 和输出 token 增长。把无关历史和整篇文档塞进请求，会更贵，也更容易答偏。

**练习**

选一个你准备反复问的问题。写下准备使用的温度，以及选这个值的原因。再判断这段提示占窗口的大致情况：很短、中等，或可能把窗口挤满。写出判断依据（有没有贴长文、有没有多轮历史）。

**自检**

- [ ] 能单独解释温度控制什么
- [ ] 能单独解释上下文窗口里都算进了哪些内容
- [ ] 温度选择和「要稳定还是要发散」对得上

### 1.3 环境与第一次调用

**要点**

- 密钥放在环境变量里。不写进源码，不提交到仓库，不打印到日志。
- 一次聊天请求至少包含：模型名、消息列表、温度。
- 成功时先读回复文本。失败时读状态码和错误信息，区分密钥错误、模型名错误、超时、余额不足。
- 同一问题至少调用两次：一次温度 0，一次温度 0.9。对比的是稳定性，不是哪次「更聪明」。

**练习**

用同一个问题各调用一次温度 0 和温度 0.9。写 5 行差异说明，写措辞、结构或是否跑题，不要只粘贴两段原文。

**自检**

- [ ] 没有看示例代码也能独立发出一次聊天请求并拿到回复
- [ ] 5 行说明里写到了两次输出的具体差异
- [ ] 密钥没有出现在代码文件和终端输出里
- [ ] 能口头说明温度和上下文窗口
