# 8. 综合项目

## 学习目标

独立交付一个小应用。这一模块不引入新概念，只把前面的能力收成一个能给别人跑的结果。

三选一，只做一个：

- 个人知识库问答：模块 5 的完整版，回答带来源，文档里没有的就拒答。
- 带工具的学习教练：出题，判断对错，再根据错题讲一次。
- 会议纪要助手：输入是已经转写好的文本，输出摘要、待办和未决问题。不要求做录音。

完成标准：换一台机器按说明能跑起来，并当场用用例演示通过与失败各一例。

## 课时

<a id="8-1"></a>

### 8.1 选定项目并写清输入输出

**要点**

- 三个题目里只留一个。另外两个写进「这次不做」。
- 输入写到能举出一条真实例子。输出写清必须包含的字段或段落。
- 单写一段「已知做不到什么」。写能力边界，例如不能听录音、不能访问未放入的文档、不能代替人做最终决定。

**练习**

用半页写下：选定的项目、一条输入例子、对应的输出必须包含什么、已知做不到什么。

**自检**

- [ ] 只选了一个项目
- [ ] 输入和输出各有一条具体例子
- [ ] 「做不到什么」写的是能力边界，能用来设计失败用例

**状态**（只勾一项）

- [x] 未开始
- [ ] 进行中
- [ ] 已完成

<a id="8-2"></a>

### 8.2 接上外部能力并准备用例

**要点**

- 至少接一种外部能力。知识库问答用检索；学习教练用出题或判题工具；会议纪要用固定步骤抽出待办，或再加一个工具。
- 外部能力要出现在一次真实请求的步骤里，不能只写在说明里。
- 准备至少 5 条自测用例。其中至少 1 条是应该拒答或应该失败的。
- 每条用例仍写输入、期望要点、怎样算失败。

**练习**

把检索或工具接到选定项目上，跑通一次。写下至少 5 条用例，标出哪一条应该失败或拒答。

**自检**

- [ ] 一次真实请求里能指出检索或工具被走到了
- [ ] 至少 5 条用例，且每条都有期望要点
- [ ] 至少 1 条用例的期望是拒答或失败

**状态**（只勾一项）

- [x] 未开始
- [ ] 进行中
- [ ] 已完成

<a id="8-3"></a>

### 8.3 换机运行并演示

**要点**

- 启动说明要包含：依赖、环境变量的名字（不写值）、一条示例命令、输入从哪里来。
- 在干净目录或另一台机器上，只按说明把应用跑起来。
- 当场演示两条用例：一条通过，一条按你事先定义的方式失败或拒答。
- 演示失败指的是用例期望中的失败，不是程序崩溃。

**练习**

按启动说明从零跑通。记录两次演示的输入和实际输出：一次通过，一次失败或拒答。

**自检**

- [ ] 说明里没有密钥的值
- [ ] 换一个干净目录后，只靠说明能跑起来
- [ ] 通过的一例符合你在 8.1 写的输出要求
- [ ] 失败的一例是事先定义的失败或拒答，记录里留有输入和输出

**状态**（只勾一项）

- [x] 未开始
- [ ] 进行中
- [ ] 已完成
