# 6. Agent 与工作流

## 学习目标

分清固定流程，和模型自己循环调用工具。

完成标准：能画出这一次请求经过了哪些步骤；循环不会无限跑。

## 课时

<a id="6-1"></a>

### 6.1 工作流

**要点**

- 工作流的步骤顺序由你写死。模型只负责其中几步的文本，例如改写查询、根据片段写摘要。
- 步骤稳定的任务用工作流：先检索再摘要，先抽取再校验格式。
- 每一步写清输入和输出。上一步失败就停，不要跳到后面假装成功。

**练习**

把「先检索笔记，再摘要成 5 条」写成步骤列表。每一步标成「程序」或「模型」，并写上一步失败时停在哪里。

**自检**

- [ ] 步骤顺序不是交给模型决定的
- [ ] 每一步都有输入和输出
- [ ] 某一步失败时，能指出流程停在哪一步

**状态**（只勾一项）

- [x] 未开始
- [ ] 进行中
- [ ] 已完成

### 6.2 Agent 循环与步数上限

**要点**

- 循环是：模型决定下一步，程序执行工具，把观察结果交回，模型再决定。
- 必须设置最大步数。到了上限就停，并说明停在哪一步、已经拿到什么。
- 步骤事先能写死的，不要放进循环。
- 每一步留下记录：选了哪个工具、参数是什么、观察结果是什么。

**练习**

实现「先检索笔记，再摘要成 5 条」。可以是写死的工作流，也可以是有上限的循环。把最大步数临时改成 1，再跑一次，确认它会停，并说明停在哪一步。然后再用正常上限跑通一次，画出实际经过的步骤。

**自检**

- [ ] 一次真实请求能画出经过的步骤
- [ ] 上限为 1 时流程会停，并说明停在哪
- [ ] 没有出现不设上限的循环

**状态**（只勾一项）

### 6.3 本次记忆与长期记忆

**要点**

- 本次记忆就是你放进这次上下文的历史和检索结果。请求结束，没有另存的内容就没了。
- 长期笔记只记稳定、用户同意留下的事实，并允许删除。
- 不要长期保存密钥、证件号，以及工具返回里的敏感字段。
- 模型回复「我记住了」只是一句话。没有写进你的存储，就不算记住。

**练习**

为你的应用列出允许长期保存的 3 类内容，和禁止长期保存的 3 类内容。禁止列表里要包含密钥。

**自检**

- [ ] 允许列表写的是可删除的稳定事实
- [ ] 密钥在禁止列表里
- [ ] 能说明「模型说记住了」不等于已经持久化

**状态**（只勾一项）

- [x] 未开始
- [ ] 进行中
- [ ] 已完成
