# 2. Prompt 与输出控制

## 学习目标

让输出稳定、可解析，而不是碰运气。

完成标准：能指出一个坏提示的问题，并改到输出可被程序解析。

### 2.1 四段式提示

**要点**

- 角色：模型以什么身份做事。例如「只根据给定材料回答的助教」。
- 任务：这一次只做一件事。一件事里再塞第二个目标，输出就会晃。
- 约束：必须遵守的格式、长度、语言，以及信息不够时怎么说。
- 示例：给一对输入和理想输出。示例比「请严谨一点」更有用。
- 四段分开写。材料不要和命令搅在同一句里。

**练习**

挑一个你真会用的任务，写成角色、任务、约束、示例四段。然后删掉「信息不够时怎么说」这一条再跑一次，记下输出在哪里开始编造。

**自检**

- [ ] 四段都能单独指出来
- [ ] 删掉约束后，能指出输出越界的具体句子

**状态**（只勾一项）

- [x] 未开始
- [ ] 进行中
- [ ] 已完成

### 2.2 少样本与格式约束

**要点**

- 少样本用 2 到 3 个完整例子。例子的格式必须和最终格式一致。
- 要交给程序解析时，写明字段名、类型，并禁止额外说明文字。
- 列表和 JSON 二选一。字段固定时用 JSON。
- 例子里放一个边界：缺少信息时用空字段，或直接拒答。不要只给顺利的例子。

**练习**

写两个例子，让模型把一句中文日程抽成 `title`、`date`、`time`。第二个例子缺时间，输出里要能看出缺的是哪一个字段。

**自检**

- [ ] 两个例子本身都能被 JSON 解析
- [ ] 缺时间的例子有明确空值，字段名仍然齐全
- [ ] 例子之外没有要求模型再写一段解释

**状态**（只勾一项）

<a id="2-3"></a>

### 2.3 失败样例改写

**要点**

- 常见失败有三种：一句话有两种理解、漏了格式约束、前后两句要求相反。
- 修改时一次只动一处，再跑一次。这样才知道是哪一句起了作用。
- 不要用「请认真一点」「你是专家」修补坏提示。

**练习**

拿一段自由问答提示，改成只输出你规定的 JSON 字段。连续运行 5 次，5 次字段都要齐全，且没有字段以外的文字。

**自检**

- [ ] 能指出原提示的一个具体问题：歧义、漏约束，或自相矛盾
- [ ] 连续 5 次输出都能被程序解析
- [ ] 5 次的字段集合与规定一致
- [ ] 改动记录能看出你一次只改了一处

**状态**（只勾一项）

- [x] 未开始
- [ ] 进行中
- [ ] 已完成
